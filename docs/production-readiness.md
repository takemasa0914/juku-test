## なぜ本番受付を停止しているか

要件定義のPhase 0が未完了であり、採用尺度・倫理審査・正式な同意文書・運用責任者・安全対応手順が未確定。これらを推測して有効化しない。独自項目にも妥当性・信頼性の実証はない。体験版のチェックボックスは実際の研究同意ではない。

## API契約（本番ゲートは初期値false）

共通：Bearer access token、非子どもロールはMFA aal2必須、サーバーで毎回本人と有効なAuthセッションを照合。60 requests/min/person。読み取りを含め秘密データはno-store。最大JSON入力20KB。

| Method | Endpoint | 内容 |
|---|---|---|
| GET | /api/v1/status | デモ／本番設定状態（公開・個人情報なし） |
| GET | /api/v1/me | 認証済み本人の最小属性 |
| GET | /api/v1/scales/eligible | 許諾・承認・対象年齢が適合する尺度 |
| POST | /api/v1/assessments | scaleVersionId、任意studyId/waveIdで回答開始 |
| GET | /api/v1/assessments/:id | 本人の途中回答 |
| PATCH | /api/v1/assessments/:id/responses | {answers:{itemId:1..5 または null}}、版数による競合防止 |
| POST | /api/v1/assessments/:id/complete | 全項目の選択確認、採点、原子的・冪等保存 |
| GET | /api/v1/reports/:id | 本人の個別レポート |
| POST | /api/v1/invitations | 256bit乱数の24h招待。DBにはハッシュのみ |
| POST | /api/v1/invitations/accept | {token}、一回限り、自己招待・同役割間を拒否 |
| POST | /api/v1/dyads/:id/permission | {scopes:[agency,dialogue]}、自分の範囲のみ |
| GET | /api/v1/dyads/:id/comparison | 双方の許可の交差範囲のみ |
| POST | /api/v1/shares | {viewerId,reportId,scopes,days}、担当教育者限定 |
| GET | /api/v1/shares/:id | 指定した教育者・有効所属だけの限定要約 |
| POST | /api/v1/shares/:id/revoke | 本人が取消 |
| GET/POST | /api/v1/consents | 本人の同意記録／承認済み文書への同意 |
| POST | /api/v1/consents/:id/withdraw | 研究撤回と利用停止を別処理 |
| POST | /api/v1/studies/:id/enrollments | 審査済み研究・対象年齢・文書版を照合 |
| POST | /api/v1/studies/:id/exports | 承認された担当研究者だけの仮名化CSV（最大5000行） |
| POST | /api/v1/deletion-requests | サービス削除申請（即時物理消去ではない） |

採点アダプタは独自体験項目の版のみ実装。尺度をDBで登録しただけでは新しい採点ロジックは実行されず、409で停止する。

## 本番接続の順序

1. 研究責任者、尺度・対象集団・倫理審査、プライバシー通知、年齢別同意、保存・削除期間、安全対応時間・担当、連絡先を確定。
2. ユーザーが指定した専用Supabaseプロジェクトを国内リージョンで作成。所在・国外移転・委託条件・料金を確認する。他案件のDBを流用しない。
3. `db/schema.sql`をステージング専用DBへ適用。Authは招待制、匿名サインイン・自己登録を無効化。メール認証と成人ロールのMFAを構成。
4. 正式な同意文書と尺度審査を登録。DBのrolesは運用者が付与し、利用者のuser_metadataから作らない。
5. 画面のデモデータストアを本番APIに接続する。デモと本番はURL／状態保存を分離し、デモの同意を移行しない。本番の心理回答・生トークンはlocalStorageに保存しない。
6. 環境変数はVercelの非公開設定へ登録。service roleをNEXT_PUBLIC変数・ブラウザ・リポジトリへ出さない。専用サーバーのIAM・秘密管理も運用レビュー。
7. ステージングで異なる本人・親子・別組織・研究者・MFA・撤回・期限切れ・セッション失効のE2Eテスト。障害時に監査が記録できなければ閲覧を返さない。
8. 承認済み版だけ公開し、`LIVE_APPROVAL_REFERENCE` と `LIVE_DATA_ENABLED=true` を設定。環境変数だけでは正式尺度の審査や画面の本番接続は完了しない。
9. 未成年向け本番利用の募集は全条件完了後。定期的な復元訓練・レート制限表の削除・依存更新・監査レビュー・削除申請処理を設定。

## PDFと集計の限界

印刷PDFはオフラインファイルなので、サーバー上の権限を取り消しても回収できない。体験版はこの点を明示。集計のn>=10/20は一次的な抑止条件であり、任意のフィルターを繰り返す差分攻撃を防止する仕組みの代わりにはならない。現在は実データの任意集計APIを公開しない。
