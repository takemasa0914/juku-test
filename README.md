# よりそいラボ — 親子心理アセスメント・研究プラットフォーム

要件定義 v0.1 をもとにした、**公開可能な体験版 + 本番向けAPI・PostgreSQL基盤**です。未承認の心理尺度や実データを公開・収集しません。全フェーズ完成版・研究で使用可能な心理検査ではありません。

## 現在できること

- 子ども／保護者の架空プロフィールで独立した回答を体験
- 4つのテーマ・18項目の独自の未検証質問。スキップ・途中保存・再開
- 逆転項目・欠測（回答率2/3）を処理する決定的採点、品質上の留意点
- 領域別の回答平均、同一版の推移、具体的な振り返りの問い
- 親子双方が許可した領域だけの比較、取り消し、端末内の招待体験
- 教育者向けの範囲・期限付き共有のシミュレーションと即時取消
- 研究同意と再連絡同意の独立管理、撤回操作の体験
- 架空の研究CSV・コードブック出力、少人数集計の抑止例
- 選択領域だけの印刷／PDF保存、カレンダー用ICS出力
- 端末データ消去、尺度カタログ、スマートフォン用レイアウト

全ての画面上の共有・研究・招待は操作体験です。入力はこの端末の localStorage に保存され、外部には送信されません。研究出力は24人×3時点の固定の架空データであり、体験用に入力した回答は含みません。教育者メモは画面内メモリのみです。サンプルの氏名・研究・倫理承認は架空です。

## 起動

Node.js 22以降。

```sh
npm ci
npm run dev
```

`http://localhost:3000` を開きます。

```sh
npm test
npm run typecheck
npm run build
npm start
```

添付アーカイブの `preview.html` は、ReactとCSSを内包したブラウザで開ける体験版です。APIは含みません。ブラウザの設定により `file://` 上の端末保存が使えない場合は、Node版を利用してください。

## GitHub / Vercel

ソース管理：`takemasa0914/juku-test`。機密情報・認証情報・実際の回答データはコミットしないでください。

1. GitHubに空のリポジトリを作り、認証済みのGit環境からソースをpush。
2. VercelでそのリポジトリをImport。FrameworkはNext.js、ビルドは`npm run build`、インストールは`npm ci`。
3. **体験版は環境変数なしで動作**。`vercel.json`でFunctionsのリージョンは東京（hnd1）を指定。
4. `GET /api/v1/status` は `mode: demo`、実データAPIは503。APIゲートが閉じていることを公開前に確認。

公開時は体験版モードを使用し、本番APIの有効化は別工程として扱います。

## 本番の準備

`docs/production-readiness.md` を必ず参照。`LIVE_DATA_ENABLED` は運用レビューの証跡であり、自動的に本番安全性を保証するものではありません。現在の画面はデモ用データストアに接続しており、本番APIへの切り替え・実アカウントのログイン／招待画面は次の接続工程です。

- `db/schema.sql` は新規専用Supabase/PostgreSQL向けDDL。既存DBに無断適用しない。
- `app/api/v1/[...path]/route.ts`：認証・MFA・採点・共有・研究抽出API基盤。
- 公開スキーマの全appテーブルはRLS有効、anon/authenticatedの権限を撤去。ブラウザからDBへ直結しない。
- サーバーだけがservice roleを使用。毎リクエストでSupabase Authのユーザー・セッション・DB上の役割・本人性を確認。
- 親・教育者・研究者・管理者はaal2を必須化。user_metadataを権限根拠にしない。
- 研究ID対応表とレート制限はprivateスキーマ。研究出力には内部ID・連絡先・自由記述・生回答を含めない。
- 監査ログの更新・削除はサーバー資格情報でも不可。
- 個別レポート・研究抽出はno-store。外部AI・アクセス解析・広告SDKなし。
- 心理尺度の項目・ライセンス許諾は同梱していない。候補尺度は公開停止。

## テスト

`node:test` + TypeScript、PGlite上のPostgreSQL実行による権限・共有・研究機能のテストを収録。

21件のテスト（DOM上での回答・再開・親子双方許可・共有取消も含む）が通過。

実Supabaseの認証・MFA・APIとDBの通し検証、ブラウザでの見た目・アクセシビリティ・スマートフォン実機検証は別途必要です。ビルド成功はそれらの代替ではありません。

## 構成

- `components/workspace.tsx`：日本語体験UI
- `lib/domain.ts`：採点、版比較、共有、CSV出力ルール
- `lib/demo.ts`：完全に架空の体験データ
- `lib/access.ts` / `lib/server.ts`：本番APIの認証・認可
- `db/schema.sql`：データモデル・原子的更新・アクセス境界
- `tests/`：採点とアクセス制御の自動テスト
- `docs/requirements-v0.1.md`：提供された要件定義の原本
- `docs/production-readiness.md`：実装状況・残作業・運用条件
